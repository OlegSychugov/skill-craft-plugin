# skill-craft — навигатор по стандарту авторинга

Навигационный навык: сам по себе короткий, глубину держит в `Референсы/`
(прогрессивное раскрытие, уровень 3 — ресурсы по мере необходимости).
Применяется при переработке черновиков из `Draft/` в чистовые skills и
plugins каталога `cowork_hub/`, при написании новых `SKILL.md` /
`plugin.yaml` и при ревизии существующих сущностей.

## Карта референсов

| Ситуация | Файл |
|---|---|
| Структурный контракт витрины: поля YAML, alias, категории, ограничения плагинов | `Референсы/METHODOLOGY.md` |
| Как писать тело навыка: краткость, нейминг, description, степень свободы, прогрессивное раскрытие, паттерны, рабочие процессы | `Референсы/SKILL-AUTHORING.md` |
| Образцы из каталога, конвенция `Референсы/`, специфика commands/agents/README | `Референсы/SKILL-AUTHORING.md`, раздел «Локальное дополнение» |
| Итоговая HTML-страница агента (клиентская презентация: видео + ссылка на пространство, по запросу после демо) | `Референсы/AGENT-HTML.md` |
| Публикация в gitverse: ветки `feature/<alias>`, PR в master (или main) | `Референсы/PUBLISHING.md` |
| Ведение графа плагинов Plugins-map.md — статусы, связи, анализ слияний | `Референсы/PLUGINS-MAP.md` |
| Совместимость с окружением Giga Cowork: stateless-песочница, системные навыки `sys-*`, лимиты вызовов | `Референсы/HARNESS-DESCRIPTION.md` |
| Тестирование поведения навыка — evals, прогон на демо-стенде, вердикт (только по явной просьбе пользователя — по умолчанию игнорируется) | `Референсы/EVALUATION.md` |
| Проектирование ИТ-системы/навыка, встраиваемого в ландшафт и процессы клиента (ETL, MCP) — только по явной просьбе пользователя, по умолчанию игнорируется | `Референсы/SYSTEM-DESIGN.md` |
| Ручное развёртывание плагина на демо-стенде — путь в UI, упаковка ZIP, привязка навыков и команд | `Референсы/auto-test.md` |
| Съёмка и монтаж демо-видео работы плагина (ролик 1:20–1:40 без «висений» и озвучки, с субтитрами) | `Референсы/DEMO-VIDEO.md` |

EVALUATION.md, SYSTEM-DESIGN.md, auto-test.md и DEMO-VIDEO.md — опциональные
слои: применяются только после явной просьбы пользователя; без неё агент их
не открывает и не требует их артефактов.

Ссылки — один уровень глубины: SKILL.md → файл `Референсы/`.

## Команды плагина

Команды — отдельные навыки этого плагина, запускаются только явно:
в Claude Code — `/skill-craft:<команда> <alias>`, в Codex — `$<команда>`.
Явный вызов команды опционального слоя и есть просьба пользователя.

| Команда | Что делает | Референс |
|---|---|---|
| `new-plugin` | черновик `backlog/01. ToDo/<x>` → плагин в `backlog/02. Testing/<alias>/` + синтетические тест-данные | METHODOLOGY.md, SKILL-AUTHORING.md |
| `review-plugin` | ревизия плагина по чек-листу приёмки, только чтение | этот файл, SKILL-AUTHORING.md |
| `test-plugin` | сборка `evals/` и вердикт по результатам прогона | EVALUATION.md |
| `deploy-plugin` | ручное развёртывание на демо-стенде через браузер | auto-test.md |
| `demo-video` | запись и монтаж демо-ролика с субтитрами | DEMO-VIDEO.md |
| `agent-page` | итоговая клиентская HTML-страница агента | AGENT-HTML.md |
| `publish-plugin` | Testing → `plugins/<alias>`, ветка `feature/<alias>`, PR | PUBLISHING.md |
| `plugins-map` | обновление узла плагина в `Plugins-map.md` | PLUGINS-MAP.md |

Жизненный цикл: `new-plugin → review-plugin → (test-plugin) →
(deploy-plugin) → (demo-video → agent-page) → publish-plugin → plugins-map`.

## Настройки окружения

Адреса и пути окружения не зашиты в навык: в тексте они записаны как
`<cfg:ключ>`, значения — в `.skill-craft.json` в корне cowork_hub.
Образец — `skill-craft.config.example.json` рядом с этим файлом.

| Ключ | Что это |
|---|---|
| `hub_repo_url` | веб-адрес репозитория витрины |
| `hub_base_branch` | основная ветка (`master` или `main`) |
| `hub_pr_url` | ссылка на создание PR, шаблон с `{base}` и `{branch}` |
| `demo_stand_url` | адрес демо-стенда |
| `video_share_url` | файлообменник для демо-роликов |
| `video_share_folder` | папка роликов на файлообменнике |
| `plugins_map_path` | путь к `Plugins-map.md` относительно корня cowork_hub |

Встретив `<cfg:ключ>`, подставь значение из файла. Файла или ключа нет —
спроси у пользователя только нужные ключи, создай/дополни
`.skill-craft.json` и добавь его в `.git/info/exclude` cowork_hub, чтобы
он не попал в коммиты. Значения не выдумывать.

## Чек-лист приёмки чистовика

Перед сдачей переработанного навыка/плагина проверь:

- [ ] Контракт `METHODOLOGY.md` выполнен (поля, alias). Категория — только
      из семи поддерживаемых backend (перечень — «Локальное дополнение»
      `METHODOLOGY.md`); новые категории в `categories.yaml` не создаются.
- [ ] Сущность отражена в `Plugins-map.md`: узел с ALIAS и STATUS, состав
      навыков и связи актуальны (`Референсы/PLUGINS-MAP.md`).
- [ ] Frontmatter валиден как YAML: `description` — одна plain-строка:
      без `|-`, кавычек и «: » (двоеточие+пробел); перечисления —
      через «—» (образец: `plugins/document-manager/plugin.yaml`);
      `name` — одна строка без «: ».
      Касается SKILL.md, `plugin.yaml`, `commands/*.md`, `agents/*.md`.
- [ ] `version` — целое число; `tags` — непустой список slug-тегов
      (обязательны при публикации — все пять полей: name, description,
      category, version, tags).
- [ ] Теги — slug: без пробелов, многословные через дефис (`база-знаний`);
      теги `plugin.yaml` и навыков плагина согласованы.
- [ ] Навык не требует пакетов вне предустановленного списка; нет
      `pip install`; интернет из `python_run` не используется; если задача
      требует публичных данных — инструкция либо вызывает `web`/`webfetch`
      (когда они доступны), либо явно помечает fallback на
      `sys-search`/`sys-retrieval` + знания модели
      (`Референсы/HARNESS-DESCRIPTION.md`).
- [ ] Файловые операции и форматы — через системные навыки (`sys-files`,
      `sys-word`, `sys-excel`, `sys-powerpoint`, `sys-pdf`), не
      `python_run`; состояние между вызовами — файлы в `/session`.
- [ ] Визуализация для пользователя — `sys-infographics` (ECharts), не
      matplotlib-PNG; сканы PDF без текстового слоя — `pdf(op="render")`,
      не OCR.
- [ ] `name` — отглагольное существительное; alias — латиница, цифры,
      дефис, подчёркивание, ≤ 64 символов.
- [ ] `description` = что делает + контекст применения, без дословных
      триггерных и анти-триггерных фраз; триггеры и неформальные сигналы —
      в разделе тела «Когда использовать (триггеры)».
- [ ] Тон и орфография выверены (тестировщик проверяет их при приёмке —
      чек-лист в `Референсы/PUBLISHING.md`).
- [ ] Степень свободы агента определена явно.
- [ ] Тело ≤ 500 строк; излишки — в `Референсы/` с оглавлением при 100+.
- [ ] Код (.py), профили (.json), демо-данные (.csv) — отдельными
      файлами в `Референсы/`, не встраиваются в SKILL.md.
- [ ] Ссылки на ресурсы — один уровень глубины.
- [ ] Многошаговые процессы — с чек-листом прогресса.
- [ ] Есть раздел «Когда использовать (триггеры)» с триггерами,
      анти-триггерами и пограничными случаями.

**Если пользователь явно запросил eval-слой (по умолчанию —
пропустить):**

- [ ] Есть `evals/` минимального набора: триггер, анти-триггер,
      пограничный; промпты — естественные формулировки без имени навыка
      (`Референсы/EVALUATION.md`).
- [ ] Градеры детерминированы где возможно; «критические ошибки» ТЗ
      покрыты обязательными градерами.
- [ ] Перед публикацией: `evals/results/<дата>/вердикт.md` = PASS
      (2 прогона/кейс на приёмке); гейт действует только при
      активированном eval-слое.
- [ ] Итоговая HTML-страница (`Демо/ИИ_агент_<имя>.html`) — только если
      пользователь её запросил; соответствует `Референсы/AGENT-HTML.md`;
      обе ссылки (видео, пространство) реальны.
- [ ] README плагина написан как пользовательское описание витрины —
      README отображается в витрине как описание плагина (назначение,
      состав, примеры запросов), не как внутренняя техзаписка.
- [ ] Ничего не выдумано: все факты черновика сохранены, дополнения помечены.

## Где живёт навык

Источник правды — `.kilo/skills/skill-craft/` в cowork_hub (оттуда его
загружает Kilo). Этот плагин — дистрибутив для Claude Code и Codex;
содержимое `Референсы/` обновляется скриптом
`scripts/sync-from-source.ps1` маркетплейса. Сборка плагина каталога
Cowork описана в команде `new-plugin`.

Действия в `cowork_hub/` (ветки, коммиты, PR) — только по
`Референсы/PUBLISHING.md` и с явной просьбы пользователя.
