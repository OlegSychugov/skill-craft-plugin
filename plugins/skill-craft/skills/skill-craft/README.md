# Тестирование поведения навыков (evals)

> **Назначение:** краткое описание eval-слоя качества для навыков и
> плагинов Cowork — зачем он нужен, что содержит и как проходит цикл
> тестирования. Самодостаточный документ для шаринга. Полная методика —
> `Референсы/EVALUATION.md` рядом с этим файлом. Слой opt-in:
> применяется только по явной просьбе пользователя, по умолчанию
> игнорируется (включая гейт публикации).

## Зачем тест-слой поведения

Чек-лист приёмки проверяет структуру, ревью — содержание. Но навык может
быть структурно безупречен и при этом не срабатывать на живой фразе
пользователя, выбирать неверные инструменты или нарушать запреты при
исполнении. Такие дефекты видны только в прогоне — их ловит eval-слой.

## Что содержит evals/

`evals/` собирается в папке тестирования плагина, рядом с синтетическими
тест-данными:

| Элемент | Назначение |
|---|---|
| `кейс-<имя>/prompt.md` | естественная формулировка (без имени навыка) + canned-ответы на вопросы агента |
| `кейс-<имя>/градеры.md` | PASS/FAIL-проверки: детерминированные и рубрики |
| `ПРОТОКОЛ_DEMO.md` | пошаговый прогон на демо-стенде Cowork |
| `get-evals-result.md` | промпт-сборщик факт-отчёта по прогонам |
| `results/<дата>/` | факты, скачанные артефакты, вердикт |

Минимальный набор кейсов — три: триггер (навык должен сработать),
анти-триггер (не должен сработать), пограничный случай (поведение по
заявленной в навыке стратегии).

## Цикл тестирования

1. **Собрать** evals: кейсы — из триггеров, анти-триггеров и пограничных
   случаев навыка; градеры — из критериев качества и критических ошибок.
2. **Прогнать** на демо-стенде Cowork по `ПРОТОКОЛ_DEMO.md`: установка
   плагина, загрузка тест-данных, кейсы по 2 прогона на приёмке.
3. **Собрать улики**: факт-отчёт (список файлов сессии,
   последовательность вызовов, вопросы, аномалии) и скачанные артефакты
   сессии.
4. **Получить вердикт**: грейдинг по градерам, таблица кейсов, итог
   PASS/FAIL.

## Что считается прохождением

- каждый кейс — PASS в обоих прогонах (на приёмке — 2 прогона на кейс);
- ни один критический градер не упал: FAIL критического = FAIL кейса;
- каждый FAIL привязан к градеру и улике (файл + место).

## Вердикт — гейт публикации

Публикация плагина в витрину допускается только при вердикте PASS
последнего прогона; гейт действует только при активированном
eval-слое — без явного запроса пользователя публикация вердикта не
требует. Материалы evals (кейсы, прогоны, результаты) — внутренние
QA-материалы: они не переносятся в публикуемый пакет плагина и не
выкладываются в витрину.

## Детали

Полная методика — структура кейсов, типы градеров, шаблоны протокола,
факт-отчёта и вердикта, правила недетерминизма и Δ-плечо (прогон без
навыка) — в `Референсы/EVALUATION.md`.
