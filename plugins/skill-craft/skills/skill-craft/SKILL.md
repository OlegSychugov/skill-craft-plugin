# skill-craft — стандарт плагинов каталога Cowork

## Как устроена работа

Пользователь приходит с целью: какую задачу и для кого должен решать
плагин. Работа идёт в два хода:

1. **План.** Умная модель разбирается в цели и в ограничениях платформы
   и пишет план плагина (`design-plugin`). Каждое решение в плане
   обосновано, а всё неизвестное помечено `<TBD>`.
2. **Сборка.** Исполнитель (та же или более простая модель) собирает
   плагин по плану (`new-plugin`) и не додумывает за пользователя.

Главное в любом артефакте — цель пользователя. Инструкции навыков
плагина тоже пишутся через цель: «цель → крупные шаги → границы», без
пошагового кода (эталон — `Референсы/SKILL-MEDIUM-FREEDOM.md`).

## Этапы и команды

Команды — отдельные навыки этого плагина. Они запускаются только явно:
в Claude Code — `/skill-craft:<команда>`, в Codex — `$<команда>`.

| Этап | Команда | Цель |
|---|---|---|
| 00 Design | `design-plugin` | цель или черновик → `ПЛАН.md` |
| 01 Create | `new-plugin` | план → плагин в `<cfg:testing_dir>/<alias>/` + тест-данные |
| 01 Create | `review-plugin` | проверка плагина по чек-листу, только чтение |
| 03 Test | `test-plugin` | evals: сборка кейсов и вердикт PASS/FAIL |
| 03 Test | `deploy-plugin` | развёртывание на демо-стенде |
| 04 Marketing | `demo-video` | демо-ролик для клиента |
| 04 Marketing | `agent-page` | клиентская HTML-страница агента |
| 02 Publish | `publish-plugin` | перенос в каталог, ветка, PR |
| 02 Publish | `plugins-map` | узел плагина в карте `Plugins-map.md` |

Порядок: `design → new → review → (test) → (deploy) → (video → page) →
publish → map`. Этапы в скобках — по просьбе пользователя; явный вызов
команды и есть такая просьба.

## Сквозные принципы

- **Не выдумывать.** Факты, ссылки и цифры берутся только из материалов
  и ответов пользователя; недостающее помечается `<TBD: что уточнить>`.
- **Необратимое — только после «да».** Удаление, перезапись, `git stash`,
  `git fetch`, push и действия на стенде выполняются с согласия
  пользователя. В master не пушить никогда.
- **Чистая папка пользователя Cowork.** Навык не создаёт служебных
  файлов в `/session`: всё, что там лежит, видно пользователю.
- **Окружение Cowork — не локальная машина.** Что доступно навыку,
  определяет `Референсы/HARNESS-DESCRIPTION.md`, а не привычки.
- **Адреса и пути — из `.skill-craft.json`.** В текстах они записаны как
  `<cfg:ключ>`; правила — `Референсы/CONFIG.md`.

## Референсы

| Файл | Когда читать |
|---|---|
| `Референсы/METHODOLOGY.md` | контракт витрины: структура, поля, 7 категорий, YAML-канон, стандарт агента |
| `Референсы/HARNESS-DESCRIPTION.md` | что умеет и чего не умеет песочница Cowork; перед проектированием навыка |
| `Референсы/SKILL-MEDIUM-FREEDOM.md` | как писать тело навыка: каркас, принципы, образец |
| `Референсы/SKILL-AUTHORING.md` | конвенции каталога: `Референсы/`, name и description, commands, README |
| `Референсы/DEMO-DATA.md` | тест- и демо-данные плагина |
| `Референсы/CONFIG.md` | ключи `<cfg:…>` и что делать без файла настроек |

Референсы этапов лежат у своих команд (`../<команда>/Референсы/`).

## Чек-лист приёмки плагина

- [ ] Контракт `METHODOLOGY.md` выполнен: 5 полей, alias, категория —
      одна из 7, YAML-канон во всех заголовках.
- [ ] Агент `agents/<alias>.md` есть и соответствует стандарту агента
      (`METHODOLOGY.md`, раздел «Стандарт агента»).
- [ ] У каждого навыка: цель, степень свободы, раздел «Когда
      использовать (триггеры)» с анти-триггерами; description без
      триггерных фраз.
- [ ] Навык не выходит за рамки harness (чек-лист
      `HARNESS-DESCRIPTION.md` §7).
- [ ] Тело SKILL.md ≤ 500 строк; код, профили и данные — отдельными
      файлами в `Референсы/`, ссылки на один уровень.
- [ ] Тест-данные по `DEMO-DATA.md`.
- [ ] README плагина написан для витрины: назначение, состав, примеры
      запросов.
- [ ] Тон и орфография выверены.
- [ ] Ничего не выдумано: факты плана и черновика сохранены, остальное
      помечено `<TBD>`.
- [ ] Если есть `evals/` — последний вердикт PASS (`test-plugin`).
