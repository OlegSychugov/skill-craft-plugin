# DEMO-VIDEO — демо-ролик плагина для клиента

Опциональный слой (как `auto-test.md`): применяется только по явной просьбе
пользователя — «запиши видео», «сними демо», «сделай ролик».

Цель — ролик, который не стыдно отправить клиенту: **40–90 с (по содержанию,
без растягивания статикой), MP4 H.264
1920×1080**, без «висений», с крупным показом результата, главами и
финальной карточкой. Делается конвейером: журнал событий при записи →
автомонтаж по журналу → автоматическая и визуальная приёмка.

Скрипты — `Референсы/Съёмка демо-видео/`:

| Файл | Назначение |
|---|---|
| `record_events.js` | внедряется в запись: видимый курсор с кругами клика + журнал событий с рамками элементов |
| `edit.example.json` | образец сценария монтажа (главы, holds, плашки, карточки) |
| `auto_edit.py` | монтаж по журналу: обрезка, вырезы, ускорение ожидания, зум, главы, карточки, MP4+WebM, обложка, VTT |
| `brand_cards.py` + `brand/` | фирменные карточки GigaCowork (титул-разделитель, финальный информационный слайд); предпросмотр — `python brand_cards.py edit.json` |
| `qa_video.py` | приёмка: длительность, формат, белый кадр, «висения» + листы раскадровки для просмотра |
| `analyze_idle.py` | быстрый поиск статичных участков в любом ролике |

Нужны Python и полный ffmpeg из `imageio-ffmpeg`. Нет пакета — предложить
пользователю `pip install imageio-ffmpeg` и ставить только после согласия.

## 1. Принципы

Так устроены современные продуктовые демо, и так же — наш ролик:

- **Сначала польза.** Титульная карточка (3 с): кто агент и что даёт —
  одной строкой. Дальше запрос, ускоренная работа, результат крупно,
  финальная карточка с 2–4 итогами в цифрах.
- **Ожидание не показываем.** Пока агент думает, экран стоит — такие куски
  сжимаются до 1–1,5 с с бейджем «Ускорено ×N». На 1x — только смысловые
  моменты.
- **Результат — главный кадр.** Каждый созданный файл открывается и
  показывается (холст/превью, прокрутка листов), итоговые цифры — с зумом.
  Финал на тексте ответа мелким шрифтом — брак.
- **Зум вместо мелкого текста.** На ключевых моментах — плавный наезд на
  нужную область (панель навыков, файл, итоговая таблица).
- **Короткие подписи.** Главы — 2–5 слов в плашке сверху; плашка снизу —
  одна строка о главном факте. Сплошные субтитры по 10 с не нужны.
- **Чистота.** В кадре только демо-пространство, демо-данные и результат:
  без списков пространств, чужих клиентов, служебных файлов и сцен отладки.

## 2. Подготовка: сценарий, стенд, демо-данные

### 2.1 Сценарий (до записи)

Запиши сценарий в `Демо/edit.json` (образец — `edit.example.json`): какие
события будут отмечены при записи, что показывается на 1x и с каким зумом,
тексты глав, плашек и карточек. Тексты — только факты из ответа агента и
материалов плагина. Согласуй сценарий с пользователем.

Типовой набор событий: `start` (пространство открыто), `send` (запрос
отправлен), `skill_panel` (видны навыки/прогресс), `file_ready` (файл
появился в «Документах»), `result_open` (файл открыт в превью),
`result_scroll` (прокрутка к итогам), `final` (финальный ответ), `findings`
(блок находок/вопросов).

### 2.2 Стенд

- Отдельное демо-пространство; запись начинается **сразу по URL
  пространства** — без списка пространств и экранов «Загрузка…».
- В пространстве нет чужих данных, лишних чатов и файлов; профиль без
  личного аватара и ФИО.
- Плагин сохраняет служебные файлы (`.pkl`, кэши, временные `.json`) вне
  «Документов» сессии или удаляет их до ответа. Если в «Документах» всё
  же видны служебные файлы — сначала чинится навык, потом запись.
- Сцены, где агент ловит и чинит свою ошибку, в клиентский ролик не идут:
  стабилизируй навык и данные, перезапиши.

### 2.3 Демо-данные

Демо-данные — лицо продукта. Правила:

- **Одна легенда** на плагин: отрасль, масштаб, город-миллионник; описана в
  `ДЕМО-СЦЕНАРИЙ.md`.
- **Деловые нейтральные названия**: две-три части, отраслевой смысл —
  «ООО «Линия Декора»», «ООО «Агро Импорт Опт»», «АО «Гостиничный комплекс
  Северный»».
- **Нельзя:** уменьшительные, цветочные и сказочные названия («Ромашка»,
  «Солнышко», «Флора», «Весенний сад»); заглушки («ААА», «Тест»,
  «Пример»); известные бренды, банки и маркетплейсы под реальными именами;
  игра слов.
- **Люди:** сотрудники — по должности или «ведомость № N»; ИП — частотная
  фамилия и инициалы; реальные ФИО и известные персоны не использовать.
- **Числа:** суммы неокруглённые и соразмерные бизнесу (`148 350`, не
  `150 000`), даты — внутри одного периода; итоги в файле сходятся.
- **Посаженные находки** (дубль, платёж без контрагента и т.п.) — как
  прежде: детерминированные, с контрольными суммами в сценарии.
- На финальной карточке — «Данные в демо вымышлены».

Генератор данных (скрипт openpyxl) хранится рядом с данными плагина, чтобы
данные можно было пересобрать.

## 3. Запись с журналом событий

Основной способ — Playwright `recordVideo` (записывается сама страница,
работает на заблокированном компьютере и поверх любых окон). Логин в
платформу берётся из профиля Playwright MCP; креды агент не запрашивает.

```
1. state = await page.context().storageState()
2. ctx = await browser.newContext({ storageState: state,
       viewport: { width: 1920, height: 1080 },
       recordVideo: { dir: '<tmp>/video', size: { width: 1920, height: 1080 } } })
3. await ctx.addInitScript({ content: <текст record_events.js> })
4. p = await ctx.newPage(); video_start_ms = Date.now()
5. await p.goto('<URL демо-пространства>')          # сразу внутрь пространства
6. дождаться отрисовки → await p.evaluate(() => __demo.mark('start', null))
7. сценарий: мышь — page.mouse.move(x, y, {steps: 25}) перед каждым кликом;
   запрос — p.keyboard.type(текст, {delay: 35});
   после каждого ключевого момента — __demo.mark('<событие>', '<селектор>')
8. сцена результата: двойной клик по каждому созданному файлу в
   «Документах» (одиночный только выделяет) → превью → «Раскрыть» на весь
   экран → mark('result_open', '<селектор превью>') → пауза 4–5 с →
   «Закрыть» → плавная прокрутка ответа агента (mouse.wheel по 120 px с
   паузами 150 мс) до сводной таблицы → mark('result_scroll', ...) →
   пауза 4–5 с
9. events = await p.evaluate(() => __demo.events())
10. path = await p.video().path(); await p.close(); await ctx.close()
```

Сохрани `Демо/events.json`: `{"video_start_ms": <п.4>, "events": <п.9>}` и
скопируй исходник в `Демо/<имя>_raw.webm`.

- Метка ставится в момент, **когда событие видно на экране** (ответ
  дописан, файл появился), селектор — элемент, на который будет зум.
- Ждать ответ агента — по появлению финального блока, не фиксированным
  `sleep`; длинное ожидание само сожмётся при монтаже.
- Превью рендерится canvas-ом: ждать плашку «Отображение может
  отличаться от оригинала», а не текст «Страница N из». Имя файла агента
  нестабильно — искать строку `.xlsx` в «Документах» по расширению.
- **Проверяй цифры в кадре.** Перед зумом на файл сверь итоговые строки с
  ответом агента: если в файле ошибка — не показывай её крупно (зум на
  исправные строки) и сообщи об ошибке навыка пользователю.
- Превью Cowork (2026-10) — растровый рендер страниц файла. В режиме
  «Раскрыть» картинка растягивается и мылится, колонки обрезаются: превью
  показывают коротко (≤ 2 с, без зума) как факт «файл открывается», а
  главную сцену результата строят на таблицах ответа агента с зумом — они
  чёткие. Превью недоступно — только таблицы ответа, с пометкой в отчёте.
- Двойной клик выделяет текст (синяя полоса в кадре): сразу после него —
  `page.evaluate(() => getSelection().removeAllRanges())`.
- **Синхронизация журнала.** `video_start_ms` берётся в том же вызове,
  что `newPage()`; взятый позже (после `goto`, в другом вызове) сдвигает все
  метки раньше видео. Проверка после записи: по листу раскадровки найти
  момент отправки запроса и сравнить с меткой `send`; разницу записать в
  `sync_offset` в `edit.json`. Метка, поставленная не в момент события, —
  исправляется в копии журнала (`events_fixed.json`, поле `t`), исходный
  журнал не правится.
- Журнал потерян или записи без журнала — разметить события вручную:
  `qa_video.py <исходник>` даёт листы раскадровки с таймкодами, по ним
  заполнить `events.json` в формате `{"type": ..., "t": <секунды>}`.

Альтернатива — запись экрана расширением браузера — только по просьбе
пользователя: требует разблокированного десктопа и монопольного фокуса.

## 4. Монтаж — auto_edit.py

```
python auto_edit.py Демо/edit.json
```

Скрипт строит таймлайн сам:

| Участок | Что делает |
|---|---|
| до `start_at` | вырезается (загрузка, переходы) |
| `holds` | 1x, окно `pre`/`post` вокруг события, плавный зум `zoom` к рамке элемента (или к `center`) |
| экран стоит (агент думает) | сжимается до `max_compressed` с, скорость ≥ `idle`, бейдж «Ускорено ×N» |
| экран меняется (идёт вывод) | ×`active` |
| после `end_at` + `end_post` | вырезается |
| `cut` | вырезается без ускорения и бейджа — простой, когда агент уже ответил, а запись идёт |
| `title` / `end` | фирменные карточки (`brand_cards.py`, §4.1) с медленным наездом камеры |
| `chapters` / `callouts` | тёмная плашка сверху слева / акцентная плашка снизу, с плавным появлением |

Поля `edit.json` — см. `edit.example.json`. Значения по умолчанию:
`speed.idle` 20, `speed.active` 3, `speed.max_compressed` 1.5,
`chapter_dur` 4 с, `callout_dur` 3 с. Ссылка на событие — `"тип"` (первое)
или `"тип#2"` (второе по счёту).

Выход: `<output>.mp4` (основной), `.webm`, `.vtt` (главы и плашки),
`_poster.png` (обложка — финальная карточка), `_timeline.json` (для
приёмки). Скрипт печатает длительность; вне 40–100 с — правь holds и
скорости, а не обрезай результат и не растягивай статику.

### 4.1 Фирменные карточки

Стиль — шаблон «GigaCowork — примеры разделителей» (ассеты в
`Съёмка демо-видео/brand/`: фоны, логотип, робот):

- `title` — **слайд-разделитель**: фон с лентами, логотип слева вверху,
  крупный заголовок SB Sans Display (`text`) и подзаголовок (`subtitle`);
- `end` — **информационный слайд**: надстрочник капсом (`eyebrow`,
  по умолчанию «РЕЗУЛЬТАТ»), заголовок (`title`), до 4 стеклянных карточек
  2×2 (`cards: [{"title": "56 секунд", "text": "от выписки до сводки"}]` —
  заголовок карточки с фирменным градиентом), робот справа, логотип
  внизу справа, сноска (`note`, «Данные в демо вымышлены»).
- Заголовок карточки — число или короткий факт (2–3 слова), текст — одна
  мысль; факты только из ответа агента.
- Перед рендером ролика посмотри карточки: `python brand_cards.py
  edit.json` → `_edit/title.png`, `_edit/end.png`.
- Нет папки `brand/` (публичная копия навыка) — рисуется фирменный
  градиентный фон без логотипа и робота.

Ориентиры holds: `send` 3 с, `skill_panel` 3–4 с (zoom 1.6–1.8),
`file_ready` 3 с (zoom 1.8), `result_open` + `result_scroll` 8–15 с
(zoom 1.3–1.5), `final`/`findings` 6–8 с.

## 5. Звук

- По умолчанию — без голоса; допустима тихая фоновая музыка (`music` в
  `edit.json`, громкость `music_db` −20 дБ, плавные вход/выход). Трек и
  права на него даёт пользователь.
- Озвучка — только по просьбе пользователя: текст привязан к главам,
  синтез — инструментом, который уже установлен или установлен с согласия
  пользователя.

## 6. Приёмка — qa_video.py

```
python qa_video.py Демо/<output>.mp4 Демо/<output>_timeline.json
```

- Автоматика: длительность 40–100 с, H.264, ≥ 1080p, ≤ 20 МБ, первый кадр
  не белый, нет статики > 3 с вне holds и карточек. Код возврата 1 —
  исправить и пересобрать.
- **Визуальная проверка обязательна:** агент открывает каждый
  `sheet_NN.png` из `<output>_qa/` (кадр каждые 2 с с таймкодом) и проходит
  визуальный чек-лист из `qa_report.md`. Автоматика не видит чужие
  пространства, служебные файлы и перекрытия — это видит только просмотр.
- Найденный дефект записи (служебный файл, сцена отладки, не открыт
  результат) — перезапись; дефект монтажа — правка `edit.json`.

## 7. Итоговая страница

Клиентская презентация по шаблону
`Референсы/Сборка HTML агента/page_template.html` — финал конвейера, лежит
в папке `Демо/` плагина рядом с роликом. Стандарт страницы — `AGENT-HTML.md`.

Порядок: загрузить MP4 на файлообменник (публичная ссылка) → заполнить
плейсхолдеры шаблона фактами из материалов плагина → проверить страницу в
браузере.

Видео-ссылка: выгрузка на `<cfg:video_share_url>`, папка `<cfg:video_share_folder>`;
автоматом через Playwright, фолбэк — пользователь загружает вручную.
Публичную ссылку проверять в чистой вкладке: страница файла должна
открываться без редиректа на авторизацию. Публикуется MP4 — он
проигрывается везде, включая PowerPoint и мессенджеры.

Пространство: ссылка того workspace, в котором записывалось демо.

Правила: ссылки только реальные (AGENT-HTML.md §5), URL не изобретать;
контент — только из материалов плагина.

## 8. Грабли

- ffmpeg из Playwright (`ms-playwright\ffmpeg-1011`) урезан (нет
  rawvideo, trim, concat, x264) — для монтажа нужен `imageio-ffmpeg`.
  Для `recordVideo` Playwright свой ffmpeg ставится
  `cmd /c "npx playwright install ffmpeg"` (`cmd /c` — политика PowerShell
  запрещает npx.ps1).
- Sandbox `browser_run_code_unsafe` не хранит переменные между вызовами:
  контекст записи искать через
  `browser.contexts().find(c => c.pages().some(p => p.url().includes('<id>')))`;
  журнал событий переживает вызовы и переходы — он в `sessionStorage`.
- Путь к видео узнавать до `page.close()`; файл валиден только после
  `close()`.
- `page.click(selector)` телепортирует курсор — для видимого движения
  сначала `page.mouse.move(..., {steps: 25})`.
- Абсолютные Windows-пути внутри filtergraph ломают парсер (`C:`):
  `auto_edit.py` запускает ffmpeg из рабочей папки `_edit/` с
  относительными именами шрифта и текстов — не менять.
- Тексты глав и плашек пишутся в файлы utf-8-sig с `expansion=none`:
  двоеточия, кавычки и `%` в тексте допустимы.

## 9. Чек-лист приёмки ролика

- [ ] Первый кадр — титульная карточка, затем сразу демо-пространство: нет
      списка пространств, экранов загрузки, белых кадров.
- [ ] В кадре нет чужих пространств и клиентов, ФИО, личных аватаров,
      служебных файлов.
- [ ] Нет «висений»: `qa_video.py` — PASS; ожидание сжато с бейджем.
- [ ] Каждый созданный файл открыт и показан ≥ 3 с; итоговые цифры
      читаются (зум) и совпадают с ответом агента.
- [ ] Нет сцен отладки агента.
- [ ] Главы и плашки короткие, без опечаток, не перекрывают результат;
      факты верны.
- [ ] Демо-данные по правилам §2.3; на финальной карточке — «Данные в
      демо вымышлены».
- [ ] 40–90 с; MP4 H.264 1080p ≤ 20 МБ + WebM + обложка + VTT.
- [ ] Листы раскадровки просмотрены агентом, визуальный чек-лист пройден.
- [ ] Итоговая страница (если запрошена): обе ссылки реальны, видео — MP4
      по публичной ссылке.
