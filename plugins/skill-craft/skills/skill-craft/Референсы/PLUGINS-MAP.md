# Ведение графа плагинов Plugins-map.md

Карта знаний каталога cowork_hub: иерархический XML-граф (категория → плагин →
внутренний навык) с сетевым слоем CrossLinks. Сжатое контекстное окно для LLM:
по графу ищутся дубли функций и кандидаты на слияние плагинов, отслеживаются
статусы публикаций.

Файл карты: `<cfg:plugins_map_path>` (путь относительно корня cowork_hub). Карта внутренняя, в gitverse
не едет и в плагин не переносится.

## Спецификация формата

Файл `Plugins-map.md`: короткая легенда (статусы, типы связей, атрибуты, дата
актуализации, правило обновления) + весь граф в одном блоке ```xml.

### Структура XML

- Корень `<KnowledgeGraph>`. Топ-уровень — 7 узлов категорий из
  `cowork_hub/categories.yaml` (например `<Аналитика_и_финансы ALIAS="analytics">`).
- Плагин — вложенный узел категории: `TYPE="IN_CATEGORY"`.
- Внутренний навык плагина — вложенный узел плагина: `TYPE="IS_PART_OF"`.
- Порядок детей внутри узла: `keywords` → `terms` → `annotation` →
  вложенные дочерние узлы → `CrossLinks`.
- `keywords`: 3–7 слов через `|`, веса 1–9 через `:` (`скоры:8|лиды:5`).
- `terms`: 0–5 терминов через `|`, веса опциональны.
- `annotation`: 1–2 предложения (из `description` манифеста). Для `remote` /
  архива — пометка источника данных.
- `CrossLinks` — только неиерархические связи:
  `<Link TARGET="Имя_узла" TYPE="..." RELEVANCE="n"/>`, RELEVANCE 1–10
  обязателен. Симметричные типы (`OVERLAPS_WITH`, `SAME_AUDIENCE`) пишутся
  один раз (у одного из двух узлов); направленные (`COMPLEMENTS`,
  `USES_OUTPUT_OF`, `REFERENCES_MATERIAL_FROM`) — от источника к цели.

### Атрибуты узлов

- Узел плагина: `ALIAS` (имя папки), `STATUS`, `VERSION` (из `plugin.yaml`,
  если есть), `SRC="local|remote"` (remote = локальной папки в `plugins/` нет),
  `KIND="plugin|skill"`, `UPDATED="ГГГГ-ММ-ДД"`.
- Узел навыка внутри плагина: только `ALIAS`.
- Узел категории: `ALIAS` (slug из `categories.yaml`).

### Словарь статусов (жизненный цикл)

| STATUS | Значение |
|---|---|
| `idea` | `<cfg:ideas_dir>` |
| `todo` | `<cfg:todo_dir>` |
| `testing` | `<cfg:testing_dir>` |
| `draft` | папка в `<cfg:plugins_dir>/` без `plugin.yaml` |
| `local` | `<cfg:plugins_dir>/` c `plugin.yaml`, нет на gitverse |
| `remote-branch` | ветка на gitverse содержит плагин, в master не влит |
| `published` | влит в `origin/master` gitverse |
| `archived` | перенесён в `<cfg:archive_dir>` |

Дедупликация по ALIAS: одна сущность = один узел со статусом самой продвинутой
стадии (`published` > `remote-branch` > `testing` > `todo` > `idea` > `draft`
> `local`; `archived` уступает любому живому статусу того же ALIAS). Прочие
локации — в `annotation` («локальная копия удалена», «тестовые материалы в
<cfg:testing_dir>»).

### Типы CrossLinks

`OVERLAPS_WITH` (функциональное пересечение — кандидат на слияние),
`COMPLEMENTS`, `SAME_AUDIENCE`, `USES_OUTPUT_OF`, `REFERENCES_MATERIAL_FROM`.
RELEVANCE ≥ 7 у `OVERLAPS_WITH` — сильный кандидат на слияние. Связь ставится
только с опорой на состав навыков и annotation обоих узлов, не «чтобы граф был
гуще».

### Именование тегов

Из отображаемого русского имени: пробелы → `_`; символы кроме букв / цифр /
`_` — словесно (plus, minus) или опустить; тег начинается с буквы; имя
уникально во всём документе. Дефис внутри составного слова заменяется
подчёркиванием (`ИТ-поддержка` → `ИТ_поддержка`). Коллизия «имя навыка = имя
плагина» (например `Финансовая_диагностика_бизнеса`) → суффикс `_навык` у узла
навыка. Кириллица в именах тегов валидна; файл в UTF-8. При переносе в
инструменты, требующие ASCII, узел идентифицируется атрибутом `ALIAS`.

## Процедура обновления и определение статуса

- Создание плагина/навыка → узел добавляется в карту сразу (обязательный шаг
  чек-листа приёмки в `SKILL.md`).
- Статус по git: `git -C <cfg:catalog_dir> ls-tree --name-only origin/master
  <cfg:plugins_dir>/` (fetch —
  только с явного разрешения пользователя; без fetch статус определяется по
  уже имеющемуся локальному `origin/master`). Локальный `origin/master` может
  отставать — статус фиксируется на момент проверки, `UPDATED` отражает дату.
- Манифест remote-плагина: `git -C <cfg:catalog_dir> show
  origin/master:<cfg:plugins_dir>/<alias>/plugin.yaml`;
  для ветки: `git -C <cfg:catalog_dir> show
  origin/<ветка>:<cfg:plugins_dir>/<alias>/plugin.yaml`. Ветку
  включать, только если она добавляет папку
  `<cfg:plugins_dir>/<alias>`, которой нет в
  master, и имя плагина не совпадает с уже опубликованным (ранняя итерация
  того же плагина узла не создаёт — пометка в annotation опубликованного узла).
  Влитые и reverted ветки — не узлы.
- Пуш ветки в gitverse → `STATUS="remote-branch"`; merge PR в master →
  `STATUS="published"` + обновить `VERSION` и `UPDATED`; архивирование в
  `<cfg:archive_dir>` → `archived`; ревизия сущности → актуализировать
  `annotation` / `keywords` / связи / `VERSION`.
- `UPDATED` — дата последней проверки/изменения узла (ГГГГ-ММ-ДД).

## Рецепт анализа слияния (для LLM)

1. Найти в графе связи `OVERLAPS_WITH` с RELEVANCE ≥ 7.
2. Для пары плагинов сравнить общие keywords их узлов навыков: пересечение
   ключевых слов подтверждает функциональное дублирование.
3. Вывод: при сильном пересечении — кандидат на слияние; при совпадении
   аудитории без совпадения функций — разграничение (уточнить триггеры в
   SKILL.md, связь оставить с примечанием).

## Правила компактности

- `annotation` ≤ 2 предложений.
- Навыки узлов `remote-branch`, `archived` и backlog-статусов не
  разворачиваются — только плагин-уровень.
- У узла навыка — только `keywords` (без `terms`/`annotation`); полный
  контент — в SKILL.md плагина.
- `KIND="skill"` — отдельные навыки `skills/` (вне плагинов): узел наравне с
  плагинами в категории. Сейчас каталог пуст — узлов нет, правило заложено.
- Категории вне справочника `categories.yaml` в ветках (`finance`,
  `procurement`, `support`) не создают новых узлов-категорий: узел кладётся в
  ближайшую допустимую категорию, расхождение фиксируется в annotation.
