# Конвенции каталога для навыков и плагинов

Здесь только то, что отличает каталог Cowork от общих практик написания
навыков. Как строить тело навыка — `SKILL-MEDIUM-FREEDOM.md`; ограничения
окружения — `HARNESS-DESCRIPTION.md`.

## Навык

- **`name`** — отглагольное существительное на русском: «Проверка
  договора», «Анализ КП».
- **`description`** — что делает навык и для кого или каких задач.
  Дословных триггерных фраз в нём нет: description отображается в
  витрине.
- **Триггеры** — в теле, в разделе «Когда использовать (триггеры)»:
  триггеры, «Не сюда:» (анти-триггеры) и пограничные случаи.
- **Степень свободы** указывается явно вместе с обоснованием: что
  решает модель, а что делает только скрипт или шаблон.
- **Ресурсы** — в подпапке `Референсы/` рядом с SKILL.md: справочники,
  шаблоны, скрипты (`.py`), профили (`.json`), данные. В SKILL.md они не
  встраиваются; ссылки ведут на один уровень, и в тексте указано, когда
  файл читать.
- **Публичный интернет** в навыке — только условно: «если доступны
  `web`/`webfetch` — собери данные через них; если нет — используй
  `search`/`retrieval` и знания модели с пометкой „ориентир по знаниям
  модели“». Не писать «интернета нет» как безусловный факт.

## Плагин

- **`plugin.yaml`** — description плагина: что делает и когда
  использовать, без деталей реализации.
- **`commands/<alias>.md`** — короткий запуск с `${аргументами}`; логика
  остаётся в навыках. Вопрос в команде задаётся по условию: «если я не
  сказал, что подготовить, спроси…».
- **`agents/<alias>.md`** — по стандарту агента (`METHODOLOGY.md` §5).
  Сквозные правила навыков (не переспрашивать, чистая папка, без
  технических слов) выносятся в «Принципы» агента, а не повторяются в
  каждом навыке.
- **`README.md`** — описание для витрины: назначение, состав,
  примеры запросов. Это не техническая записка.
- Клиентская HTML-страница в корень плагина не кладётся: она делается
  командой `agent-page` в папке `Демо/`.
