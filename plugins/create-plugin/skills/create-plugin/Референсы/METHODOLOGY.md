# Оформление плагина для витрины Cowork

Что проверяет витрина (cowork_hub) и backend Cowork. Нарушение любого
пункта ломает импорт или публикацию. Здесь только оформление; как агент
работает и говорит с пользователем — `../SKILL.md`.

## 1. Репозиторий витрины

```
categories.yaml        справочник категорий (идентификатор — поле slug:)
skills/<alias>/        отдельные навыки
plugins/<alias>/       плагины
```

Имя папки — это alias сущности: латиница, цифры, дефис, подчёркивание,
не длиннее 64 символов; уникален в пределах своего типа.

## 2. Плагин

```
plugins/<alias>/
  plugin.yaml
  README.md                 показывается в витрине как описание плагина
  agents/<alias>.md         обязателен, минимум один
  skills/<alias>/SKILL.md   (+ Референсы/ с ресурсами навыка)
  commands/<alias>.md       по необходимости
```

- Компонентов каждого типа — не больше 20.
- `ui.entry` в `plugin.yaml` необязателен; если указан, файл должен
  существовать, иначе плагин не синхронизируется.
- У навыков внутри плагина поля `category` нет: категория задаётся
  только плагину целиком.

```yaml
# plugin.yaml
name: Синхронизация лидов CRM
description: Синхронизирует и оценивает лидов между CRM и Cowork — от выгрузки до приоритета
category: sales
version: 2
tags: [crm, лиды]
```

## 3. Категории — только 7

Backend Cowork принимает только эти значения `category`, даже если в
`categories.yaml` есть другие:

`analytics` (Аналитика и финансы), `documents` (Документы и право),
`management` (Менеджмент и HR), `sales` (Продажи и клиенты), `research`
(Исследования и внедрение ИИ), `productivity` (Продуктивность),
`development` (Разработка).

Новые категории не создавать: подобрать ближайшую из семи.

## 4. YAML-канон заголовков

Распространяется на `plugin.yaml`, `SKILL.md`, `agents/*.md` и `commands/*.md`.
Hub не разбирает блочные скаляры и ломается на «: ».

- `description` — одна plain-строка: без `|-`/`>`, без кавычек, без «: »
  (двоеточие с пробелом) в тексте; перечисления — через «—».
- `name` — одна строка без «: ».
- `tags` — slug: строчные, без пробелов, многословные через дефис
  (`база-знаний`); одинаковые в `plugin.yaml` и навыках плагина.
- При публикации обязательны все 5 полей плагина: `name`, `description`,
  `category`, `version` (целое), `tags` (непустой список).
- Заголовок закрывается одним `---`.

## 5. Навык

- **`name`** — отглагольное существительное на русском: «Проверка
  договора», «Анализ КП». Под этим названием агент упоминает навык, и его
  может услышать пользователь.
- **`description`** — что делает навык, для кого и какой результат даёт.
  Он показывается в витрине, поэтому триггерных фраз и «не сюда» в нём
  нет — они в теле, в разделе «Когда использовать (триггеры)».
- **Тело** — по каркасу `../SKILL.md` §2, не больше 500 строк.
- **Ресурсы** — в подпапке `Референсы/` рядом с SKILL.md: справочники,
  шаблоны, скрипты (`.py`), профили (`.json`). В SKILL.md они не
  встраиваются; ссылки ведут на один уровень, и в тексте сказано, когда
  файл читать или запускать. У длинного справочника — оглавление в начале.
- Пути внутри навыка — относительные, через `/`.

## 6. Команда

- В заголовке обязательны `name` и `description`.
- Тело — короткая инструкция на русском. Логика остаётся в навыке.
- **Параметров `${…}` нет** — недостающее агент спрашивает сам
  (`../SKILL.md` §8).

```markdown
---
name: Спрогнозировать кассовые разрывы
description: Показывает, в какие недели может не хватить денег и что с этим сделать
---

Если я не прислал план платежей — попроси его. Затем подготовь прогноз
кассовых разрывов: по неделям, где не хватает денег и что можно сделать.
```

## 7. README и демо

`README.md` показывается в витрине как описание плагина. Его читает
пользователь до первого запуска: владелец или сотрудник без технической
подготовки. README отвечает на три вопроса: что агент сделает, что ему
дать, чтобы ответы были точными, и чего от него не ждать. Это не
техническая записка и не пересказ промптов.

### Разделы — в этом порядке

| Раздел | Что в нём | Обязателен |
|---|---|---|
| `# <name из plugin.yaml>` и абзац под ним | что делает агент и для кого, 2–3 предложения словами пользователя | да |
| На что опирается агент | откуда агент берёт факты: документы пространства → доверенные источники → вопрос пользователю; что он не берёт из памяти (ставки, сроки, даты, цены) и что делает, если подтверждения нет | если результат зависит от норм, дат или правил компании |
| Что умеет | таблица «Задача — Что прислать — Что получите»; задача — name навыка | да |
| Команды | названия команд списком | да |
| Что загрузить в документы пространства | конкретные документы, для какой задачи каждый и что будет без него | да |
| Чего не ждать от агента | границы зоны и действия, которые агент не делает | да |
| Примеры запросов | 3–5 запросов словами пользователя | да |
| Известные ограничения платформы | дефекты платформы, которые промпт не закрывает | если есть |
| Индустриальные теги | последний раздел: теги отраслей из закрытого списка — `#Недвижимость`, `#АПК`, `#Ритейл`, `#Промышленность`, `#Госсектор`; дописывается при публикации (`publish-plugin`) | да, к публикации |

### «Что загрузить в документы пространства»

Главный раздел для точности ответов: агент сначала ищет в документах
пространства методику, правила, шаблоны и справочные данные компании
(§9). Чего там нет, он либо проверяет в открытых источниках, либо
спрашивает, либо — для шаблона — предлагает загрузить свой или сделать
документ в стандартном виде.

- Перечисли **конкретные документы** — названием, понятным пользователю:
  «карточка компании с реквизитами», «учётная политика или рекомендации
  бухгалтера», «свои шаблоны счёта и акта в Word», «правила маршрутизации
  обращений», «прайс и регламент доставки», «календарь акций».
- У каждого — **для какой задачи** он нужен и **что будет без него**:
  «агент спросит реквизиты», «сделает документ в стандартном виде»,
  «проверит сроки в открытых источниках», «не сможет сравнить цены».
- Отдельно — что стоит **сохранить в пространство после первого
  запуска**, чтобы следующие находили сами: профиль, журнал, заполненные
  правила.
- Если пространства изолированы, а документ живёт в другом пространстве, —
  так и скажи: «положите прайс сюда, из „Базы знаний“ он агенту не виден».

```markdown
## Что загрузить в документы пространства

- Карточку компании с реквизитами — для счетов и актов; без неё агент
  спросит реквизиты в чате.
- Свои шаблоны счёта и акта в Word — агент заполнит их; без них спросит,
  загрузите ли вы шаблон или сделать документ в стандартном виде.
- Учётную политику или рекомендации бухгалтера — для выбора режима; без
  них агент проверит правила на сайте ФНС и назовёт источник.
```

### «Чего не ждать от агента»

Короткий честный список, чтобы пользователь не ждал невозможного и не
разочаровался на первом запуске:

- **вне зоны** — что делают другие плагины, по названию плагина: «прогноз
  кассовых разрывов — плагин „Финансовое планирование ММБ“»;
- **действия за человеком** — по таблице полномочий `../SKILL.md` §1:
  агент не отправляет письма и документы контрагентам, не проводит
  платежи, не сдаёт отчётность, не меняет оригиналы без подтверждения;
- **без данных не отвечает** — чего нет в документах и источниках, агент
  не заполняет «из общих знаний» и не подставляет из памяти: он скажет, что
  прислать;
- **зависит от условий стенда** — например, «проверка ставок в интернете
  работает, если включён поиск; без него агент попросит подтвердить».

Не путай с «Известными ограничениями платформы»: здесь — как задуман
плагин, там — сбои платформы (английская лента, неудачный шаг на виду,
карточка вопроса под панелью), которые промпт не закрывает.

### Правила текста

- Обращение — на «вы», язык пользователя, бизнес-термины предметной
  области.
- Без alias, имён тулов, путей, `Референсы/`, `<TBD>`, слов «навык»,
  «HITL», «assist»; соседние плагины — по названию.
- Без конкретных ставок, сроков и цен — README устаревает так же, как
  промпт (§9).
- Без таблицы «Компонент — Alias — Назначение»: состав виден из «Что
  умеет» и «Команды».
- Обещания README совпадают с поведением агента: всё, что сказано в «Что
  умеет» и «Чего не ждать», есть в агенте и навыках.
- Объём — один экран, до 60 строк.

### Демо

Клиентская HTML-страница в корень плагина не кладётся: она делается
командой `agent-page` в папке `Демо/`.

## 8. Агент (`agents/<alias>.md`)

Агент — это то, кем плагин является для пользователя: он выбирает
навык под ситуацию и знает границы своей зоны. При развёртывании тело
агента становится полем «Инструкция» на стенде, поэтому без агента
навыки остаются без маршрутизации.

**Контракт.** Минимум один агент; главный по умолчанию —
`agents/<plugin-alias>.md`. Поле `skills` перечисляет все навыки плагина
и только их (в обе стороны: чужие навыки витрина не пропустит, навык без
агента не будет вызываться).

| Поле | Правило |
|---|---|
| `name` | роль, существительное-деятель («Рекрутер», «Аналитик встреч»); исключение из правила отглагольного `name` навыков |
| `description` | что агент ведёт и в каком охвате («от … до …»), по YAML-канону |
| `skills` | alias всех навыков плагина — **единственное место, где пишутся alias** |
| `temperature` | необязательно: 0.2 — расчёты и право, 0.3 — по умолчанию, 0.4–0.5 — тексты |

Стенд при ручном развёртывании игнорирует `skills` и `temperature`, но
витрина их проверяет — поэтому заполнять всегда.

**Тело** (25–60 строк, обращение на «ты»). Агент маршрутизирует, но не
исполняет: шаги и справочники остаются в навыках. Навыки в теле — по
`name`, без alias. Внутренних терминов (assist, HITL) нет: тело читает
модель, но его формулировки она повторяет пользователю.

```markdown
---
name: <Роль>
description: Ведёт <область> — от <начало> до <результат>
skills: [<skill-a>, <skill-b>]
temperature: 0.3
---

Ты — <роль> для <кого>: <чем помогаешь, словами пользователя>.

## Роль
<Что умеешь; что решает сам пользователь.>

## Навыки
1. **<name навыка A>** — когда <ситуация словами пользователя>; даёт <результат>.
2. **<name навыка B>** — когда <ситуация>; даёт <результат>.

## Принципы
1. Выбери навык по задаче: <ситуация> → «<name A>»; <ситуация> → «<name B>».
2. Делай то, о чём просили; спрашивай, только если без ответа нельзя двигаться.
3. Перед работой с таблицей, документом или PDF включи системный навык этого
   типа файлов.
4. Говори бизнес-терминами предметной области.
5. Решает пользователь: <что именно>.
<!-- остальные короткие принципы — по ../SKILL.md §9, только нужные плагину -->


## Границы
- <Что вне зоны.>
- <Смежная задача> — плагин «<Название>».
```

## 9. Факты не из памяти

Модель хорошо знает устойчивое (что такое денежный поток) и плохо —
изменчивое (ставки, сроки, переносы праздников). Навык, где от такого
факта зависит результат, указывает, откуда факт берётся.

| Класс | Примеры | Откуда |
|---|---|---|
| Устойчивые знания | понятия, общая структура отчёта | знания модели |
| Версионируемые правила | налоговые ставки и сроки, лимиты, перечни видов деятельности, производственный календарь, праздники | справочник в `Референсы/` навыка или проверенный официальный источник в интернете |
| Оперативное состояние | сегодняшняя дата, остаток, статус платежа | текущее время платформы, данные пользователя или его системы |

- **«Сегодня»** — только по текущему времени платформы; сроки, просрочки
  и срочность считаются от него, а не от даты документа.
- **Справочник правил** хранит: источник, юрисдикцию (регион), период
  действия (с — по), дату проверки. Если справочник не покрывает нужную
  дату или регион — зависимая часть не считается, пользователю говорится
  об этом простыми словами; правдоподобное значение не подставляется.
- Перенос факта в `Референсы/` не делает его актуальным: у справочника
  есть владелец и порядок обновления.

**Грязные входные данные.** Порядок: прочитать → найти проблемы →
исправить только однозначное (пробелы, формат числа и даты) → спорное —
на решение пользователю → считать. Дубли, похожие платежи, платежи без
контрагента, переводы между своими счетами не удаляются и не берутся в
расчёт молча — сначала таблица «проверьте».

## 10. Чек-лист оформления

- [ ] Структура плагина по §2; компонентов каждого типа ≤ 20.
- [ ] `plugin.yaml`: все 5 полей, категория — одна из 7, YAML-канон.
- [ ] У каждого навыка `name` и `description` по §5; триггеры в теле.
- [ ] Ресурсы в `Референсы/`, ссылки на один уровень, тело ≤ 500 строк.
- [ ] Команды по §6, без `${…}`.
- [ ] Агент по §8: `skills` ↔ `skills/` в обе стороны; разделы «Роль»,
      «Навыки», «Принципы», «Границы»; в теле нет alias и assist/HITL;
      маршрутизация «ситуация → name навыка» покрывает все навыки.
- [ ] Навыки, где важны даты, ставки или нормы, называют источник по §9.
- [ ] README по §7: разделы в порядке таблицы; есть «Что загрузить в
      документы пространства» (документ — для чего — что без него) и
      «Чего не ждать от агента»; без alias, путей, ставок и `<TBD>`.
- [ ] К публикации README заканчивается разделом «Индустриальные теги»
      с тегами только из закрытого списка §7.
