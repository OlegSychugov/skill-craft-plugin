Проблематика

Бизнес-проблемы при оценке предложений поставщиков

📋

Ручная обработка множества файлов

Закупочные процедуры включают множество файлов предложений от разных поставщиков. Специалисту необходимо открыть, сопоставить и перенести данные из каждого документа в единую форму. Ручное сведение занимает часы, повышает риск пропуска позиции, ошибки при переносе и потери актуальной версии файла.

⚖️

Субъективность оценки

Разные специалисты могут по-разному интерпретировать одни и те же критерии соответствия и формулировки поставщиков. Без единого стандарта проверки результаты оценки становятся несогласованными, а обоснование выбора поставщика требует дополнительной ручной сверки.

🔍

Сложность сравнения характеристик

Технические спецификации содержат нормативные документы, ГОСТ и ТУ, маркировки, классы прочности, параметры давления и комплектность. Для корректного сопоставления нужно извлекать значения из разных форматов, нормализовать их и учитывать допустимые аналоги. Ручное сравнение требует глубокой экспертизы и привлечения технических экспертов для выполнения такой оценки.

⏱️

Длительный цикл закупки

Техническая оценка затягивает выбор поставщика: каждое несоответствие необходимо выявить, проверить и документировать причину. Пока специалисты формируют свод и готовят заключения вручную, увеличивается длительность закупочной процедуры и нагрузка на технических экспертов.

Архитектура решения

Двухэтапный процесс обработки

1

Этап 1: Свод предложений

Навык: «Свод предложений поставщиков»

Пользователь загружает агенту технические требования для закупки и технические предложения поставщиков, после чего агент анализирует документы, сопоставляет позиции и формирует единую матрицу требований и предложений. Итоговый файл «Свод предложений поставщиков.xlsx» полностью по структуре и оформлению соответствует требованиям ННК. Колонка технического соответствия остаётся пустой.

⚠️ Критически важно

На этом этапе агент НЕ выполняет техническую оценку. После завершения этапа 1 агент останавливается и ожидает явного запроса пользователя на переход к этапу 2.

2

Этап 2: Техническая оценка

Навык: «Техническая оценка предложений поставщиков»

Пользователь сначала проверяет подготовленный файл «Свод предложений поставщиков.xlsx», предоставляет агенту набор технических критериев для оценки, а затем запускает работу агента. Агент проверяет каждое предложение поставщика по соответствию критериям, выдаёт общую оценку и детально указывает, какие критерии соответствуют требованиям, а какие не соответствуют. Итоговый файл «Протокол технического заключения.xlsx» полностью по структуре и оформлению соответствует требованиям ННК.

Условие перехода: файл свода проверен пользователем + пользователь запросил оценку + предоставлен набор технических критериев

✅ Результаты
Выполнена техническая оценка предложений поставщиков. Результат предоставлен в виде Excel-файла «Протокол технического заключения.xlsx».

Входные данные

Файлы, необходимые для работы агента

📄 Файл технических требований заказчика

Формат: Excel (.xlsx)

Ключевые поля: № п/п, Наименование МТР, ГОСТ (ТУ), Заказчик, Ед. изм., Количество, Плановый срок поставки

Структура: заголовки в строках 12-13, строка 14 — нумерация колонок, данные начинаются со строки 15

Пример: «Техническое требования Заказчика.xlsx»

📦 Файлы предложений поставщиков

Формат: Excel (.xlsx)

Шаблон имени: N.Техническое предложение.xlsx (где N — номер поставщика)

Ключевые поля: № п/п, Условное обозначение МТР, Изготовитель, Ед. изм., Количество, Срок поставки

Пример: «1.Техническое предложение.xlsx», «2.Техническое предложение.xlsx», ... «6.Техническое предложение.xlsx»

📋 Файл критериев технической оценки

Формат: Excel, PDF, DOCX, Markdown, TXT

Содержание: таблица критериев с требуемыми значениями и условиями несоответствия; детализированные правила проверки соответствия для сложных технических требований.

Пример критериев: Нормативный документ (ТУ 1469-001-82914072-2011 или аналог), Тип конструктивного исполнения (ТСФ/ТФ/РТСФ), Рабочее давление (6,3 МПа), Класс прочности (К52), Комплектность (ПЗК и ФПЗ), Срок поставки (≤90 дней)

Важно: файл должен быть предоставлен ДО начала этапа 2

Как получить: если файл отсутствует, GigaCowork может подготовить его автоматически — загрузите файл технических требований заказчика в чат и попросите выделить технические критерии для оценки.

Критерии технической оценки

Пример структуры критериев

№ Критерий Требуемое значение Условие несоответствия
1 Нормативный документ ТУ 1469-001-82914072-2011 или аналог ТУ отличается и не указан аналог
2 Тип конструктивного исполнения Сварной фланцевый (ТСФ/ТФ/РТСФ) Отсутствуют индексы ТСФ/ТФ/РТСФ
3 Рабочее давление 6,3 МПа Давление < 6,3 МПа или не указано
4 Класс прочности материала К52 Класс ниже К52 или не указан
5 Климатическое исполнение УХЛ Исполнение отличное от УХЛ или не указано
6 Комплектность ПЗК и ФПЗ в комплекте Отсутствует ПЗК и/или ФПЗ
7 Срок поставки Не более 90 календарных дней Срок превышает 90 дней

📝 Правила извлечения данных

Нормативные документы: извлекать только значение после «НД:» (например, «ТУ 24.20.40-003-34713450-2020»), слово «аналог» сохраняется

Тип конструктивного исполнения: извлекать только короткий код (ТСФ, ТФ, РТСФ), а не полное наименование

Рабочее давление: «кл.600» не преобразуется в МПа без явного правила — писать «предложено не указано»

Комплектность: искать ПЗК, ФПЗ, ФЗК в маркировке, включая фрагменты через дефис (ТФ-ПЗК-ФЗК)

Этап 1

Формирование свода предложений поставщиков

1

Активация навыка «Свод предложений поставщиков»

Агент активирует навык «Свод предложений поставщиков» и получает информацию о потребности и предложения поставщиков.

2

Чтение требований заказчика

Поиск файла по заголовкам: № п/п, Наименование МТР, ГОСТ (ТУ), Заказчик, Ед. изм., Количество. Данные извлекаются начиная со строки 15.

3

Заполнение клиентского блока

Перенос данных из требований заказчика в колонки A:G. Источник K → выходная B, L+M → C, N → D, P → E, Q → F, R → G.

4

Заполнение блоков поставщиков

5 информационных колонок заполняются данными поставщика. Колонка «Техническое соответствие/причина несоответствия» остаётся ПУСТОЙ.

5

Применение стилей

Заливки: A:G зелёные (F0FFF0), заголовки поставщиков жёлтые (FFFF00), данные светло-жёлтые (FFFFE0). Шрифты: Arial 8 pt. Границы: тонкие по всему периметру.

6

Сохранение и проверка

Файл «Свод предложений поставщиков.xlsx» сохраняется через openpyxl. Агент останавливается и сообщает пользователю о завершении этапа 1.

✅ Результат этапа 1

Файл: «Свод предложений поставщиков.xlsx»

Содержание: полная матрица требований заказчика и предложений всех поставщиков. Колонка технического соответствия пустая.

Следующий шаг: пользователь пишет «выполни техническую оценку» и прикладывает файл критериев (если ещё не приложен).

Этап 2

Техническая оценка предложений

1

Активация навыка оценки

Только после явного запроса пользователя («выполни техническую оценку», «переходи к оценке», «заполни протокол») агент активирует навык «Техническая оценка предложений поставщиков».

2

Чтение файла критериев

Агент читает файл критериев (Excel/PDF/DOCX/TXT/MD), преобразует правила в структурированный чек-лист: название критерия, поле проверки, требуемое значение, способ сравнения.

3

Нормализация данных

Перед сравнением значения нормализуются: убираются пробелы, приводится регистр, извлекаются нормативные документы после «НД:», короткие коды конструктивного исполнения (ТСФ/ТФ/РТСФ), элементы комплектности (ПЗК/ФПЗ/ФЗК).

4

Оценка по критериям

Двойной цикл: строка позиции → блок поставщика. Для каждой ячейки применяются все релевантные критерии. Результаты делятся на «соответствует» и «не соответствует».

5

Формат заключения

Первая строка: «Соответствует» или «Не соответствует». Далее перечисление критериев с разделением на соответствующие и не соответствующие.

6

Сохранение протокола

Файл «Протокол технического заключения.xlsx» сохраняется с заполненными ячейками технического соответствия. Структура, стили, объединения исходного свода сохраняются.

Как работать с агентом

Быстрый старт

📁 Загрузка файлов

Загрузите в чат: (1) файл технических требований заказчика, (2) файлы предложений поставщиков вида N.Техническое предложение.xlsx, (3) файл критериев технической оценки (можно на этапе 2).

🚀 Запуск этапа 1

Напишите: «сформируй свод предложений поставщиков». Агент создаст файл «Свод предложений поставщиков.xlsx» и остановится.

⚡ Переход к этапу 2

Напишите: «выполни техническую оценку» и приложите файл критериев (если ещё не приложен). Агент заполнит протокол технического заключения.

📋 Генерация критериев

Если файл критериев отсутствует — загрузите файл с потребностью в чат и попросите коворк выделить технические критерии для оценки. Коворк подготовит файл критериев автоматически.

💡 Ключевые команды

«сформируй свод предложений поставщиков» — запуск этапа 1

«выполни техническую оценку» — запуск этапа 2

«переходи к оценке», «заполни протокол» — альтернативные команды для этапа 2

«выдели технические критерии для оценки» — генерация файла критериев коворком; предварительно загрузите файл «Технические требования заказчика»
