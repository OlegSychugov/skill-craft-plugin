> **Условие применения:** документ применяется, когда пользователь просит
> развернуть/установить плагин на демо-стенде вручную («разверни плагин»,
> «установи из Testing-папки на стенде»). Без просьбы — не выполнять.
> Не является гейтом публикации: в отличие от eval-слоя (`EVALUATION.md`)
> этот путь ничего не блокирует — он лишь доводит плагин до работающего

> расхождении интерфейса с описанием — проверять по факту: источник

## 1. Суть и место в процессе

Развёртывание — третий слой контроля плагина: структура и поведение
проверены раньше, установка делает плагин доступным живому пользователю
стенда.

| Слой | Инструмент | Статус |
|---|---|---|
| Структура | чек-лист приёмки skill-craft | есть |
| Поведение | evals, прогон по `ПРОТОКОЛ_DEMO.md` (`EVALUATION.md`) | по запросу пользователя (opt-in) |
| Развёртывание | путь в UI стенда (этот документ) | по запросу пользователя |

Связь с eval-слоем: `ПРОТОКОЛ_DEMO.md` из `EVALUATION.md` начинается с
шага «установить плагин из Testing-папки на демо-стенде» и предполагает,
что установка уже выполнена. Эту установку закрывает данный документ —
разделы 3–7 описывают её дословно, раздел 8 даёт проверку результата.

## 2. Предусловия

- Плагин лежит в Testing-папке по стандарту skill-craft:
  `plugin.yaml`, `agents/*.md`, `skills/<alias>/SKILL.md`,
  `commands/*.md`. Агент обязателен (`AGENT-MD.md`): без `agents/*.md`
  развёртывание не начинать — инструкция агента не сочиняется на стенде.
- Открыта сессия на `<cfg:demo_stand_url>`. Логин выполняет
  пользователь: агент не ищет и не запрашивает креды — их даёт
  пользователь сам, по собственной инициативе.
- Определена карта источника полей — что откуда копировать:

| Источник | Поля | Куда на стенде |
|---|---|---|
| `plugin.yaml` | `name`, `description` | форма пространства |
| frontmatter `agents/*.md` | `name`, `description` | форма агента |
| тело `agents/*.md` после `---` | инструкция | поле «Инструкция» агента |
| frontmatter `commands/*.md` | `name`, `description` | форма команды |
| тело `commands/*.md` | инструкция | поле «Инструкции» команды |

## 3. Создание пространства

1. Открыть `/workspaces` → кнопка «Создать пространство» (ведёт на
   `/workspaces/new`).
2. Заполнить поля «Название» и «Описание» — из `name` и `description`
   файла `plugin.yaml`.
3. Нажать «Создать» → редирект на `/workspaces/<uuid>` — запомнить
   `<uuid>` пространства: дальнейшие шаги идут внутри него.

## 4. Создание агента

Внутри пространства: вкладка «Агенты» → «Создать агента». Три
обязательных поля:

- «Название» ← frontmatter `name` агента;
- «Описание» ← frontmatter `description` агента;
- «Инструкция» ← тело md-файла ПОСЛЕ закрывающего `---`. Frontmatter
  не копировать: поля `skills:` и `temperature` интерфейс игнорирует —
  привязка навыков выполняется отдельным шагом (раздел 7).

Нажать «Сохранить» → редирект на
`/workspaces/<ws>/agents/<uuid>/settings`.

## 5. Загрузка навыков

Вкладка «Навыки» → «Добавить навык» → в подменю выбрать «Загрузить
файл навыка» (не «Написать инструкцию» и не «Добавить из витрины»).

Упаковка ZIP (критично):

- input принимает **один** файл `.md` или `.zip`; папку можно передать
  только через drag&drop;
- **нельзя** упаковывать `Compress-Archive` (PowerShell): записи с `\`
  в путях дают ошибку валидации «Обратная косая черта в пути
  запрещена»;
- **нужно** упаковывать tar'ом — пути внутри ZIP получаются с `/`:

```
tar -a -c -f <alias>.zip -C <путь\к\skills> <alias>
```

- один навык = один ZIP, внутри — папка-корень `<alias>/SKILL.md`.

Цикл на каждый навык:

1. «Добавить навык» → «Загрузить файл навыка».
2. Зона «Перетащите файл или папку…» → выбрать `<alias>.zip`.
3. «Далее» → появляется карточка навыка со статусом «Добавлено».

Подтверждение успеха — статус «Добавлено» в каталоге навыков; цикл
повторить для всех навыков плагина.

## 6. Создание команд

1. Открыть вкладку «Команды» (в меню «Ещё вкладки») → «Управление
   командами».
2. «Создать команду» — кнопка в правом верхнем углу каталога.
3. Заполнить поля: «Имя команды» ← frontmatter `name`,
   «Описание» ← frontmatter `description`, «Инструкции» ← тело файла.
4. Нажать «Создать команду» — диалог закрывается сам.

Повторить цикл для каждой команды плагина: диалог не поддерживает
массовое создание, после закрытия сразу открывать следующий.

## 7. Привязка к агенту

В настройках агента `/workspaces/<ws>/agents/<uuid>/settings`:

- «Добавить в «Навыки»» → открывается каталог загруженных навыков →
  нажать «Добавить» у каждого навыка плагина (кнопка меняется на
  «Убрать»). Системные навыки уже подключены — их не трогать.
- «Добавить в «Команды»» → аналогично по каждой команде плагина.
  Системную команду «Узнать о возможностях чата» не добавлять.
- Нажать «Сохранить» внизу формы. Без «Сохранить» привязки теряются.

## 8. Верификация

Счётчики в настройках агента: «Навыки» = 11 системных + N плагиновых;
«Команды» = M (число команд плагина).

Чек-лист приёмки развёртывания:

- [ ] пространство видно в списке `/workspaces`;
- [ ] агент во вкладке «Агенты» пространства;
- [ ] каждый навык в каталоге со статусом «Добавлено»;
- [ ] каждая команда в списке вкладки «Команды»;
- [ ] счётчики «Навыки» и «Команды» в настройках агента совпадают с
      ожиданиями;
- [ ] форма настроек агента сохранена (после «Сохранить»).

## 9. Подводные камни браузерной автоматизации (Playwright)

| Симптом | Причина | Обход |
|---|---|---|
| `Ref not found` при клике | refs меняются после каждого диалога/действия | искать элемент заново (find по тексту) перед каждым кликом |
| `browser_file_upload` не срабатывает | доступен только при открытом modal state «File chooser» | сначала клик по зоне выбора файла, затем upload |
| `File access denied ... outside allowed roots` | файл лежит вне разрешённых корней | скопировать ZIP в разрешённый корень (рабочая папка), загрузить, после загрузки удалить копию |
| «Можно загрузить только один файл» | в input остался прежний файл | «Удалить выбранный файл», затем выбирать заново |
| нужно проверить счётчики | их значения в тексте страницы | regex по `document.body.innerText`: `/(Навыки|Команды|Интеграции)\s*\n?\s*(\d+)/g` |
