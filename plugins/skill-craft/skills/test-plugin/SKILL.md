# test-plugin — evals: сборка и вердикт

Два режима для плагина из `backlog/02. Testing/<alias>/`:

- `test-plugin <alias>` — собрать `evals/`;
- `test-plugin <alias> grade <дата>` — проградировать
  `evals/results/<дата>/` и написать `вердикт.md`.

Явный вызов команды — это и есть просьба пользователя включить eval-слой.

## Предусловия

- Рабочий корень — cowork_hub; плагин в `backlog/02. Testing/<alias>/`.
  Нет alias — покажи доступные и спроси.
- Загрузи навык `skill-craft` и прочитай
  `../skill-craft/Референсы/EVALUATION.md` целиком — он задаёт структуру,
  шаблоны и правила; содержимое здесь не дублируется.

## Режим «сборка»

- [ ] 1. Прочитай SKILL.md плагина (и черновик в `backlog/01. ToDo/`, если
      есть): триггеры, анти-триггеры, пограничные случаи, критерии
      качества, критические ошибки.
- [ ] 2. Кейсы (§3): минимум триггер, анти-триггер, пограничный.
      Промпты — живые формулировки без имени навыка; canned-ответы на
      `question` агента. Нет источника для кейса — `<TBD>` и вопрос в
      отчёт, не выдумывать.
- [ ] 3. Градеры (§4) в `кейс-<имя>/graders.md`: артефакт-детерминированные,
      инструментальные, рубрика; критические ошибки — обязательные.
- [ ] 4. `ПРОТОКОЛ_DEMO.md` по шаблону §5 и `get-evals-result.md` по §6 —
      с вшитыми именами кейсов и ожидаемыми артефактами.
- [ ] 5. Fixtures не копировать — ссылаться на файлы «Данные агента …».
      Если их нет — предложить создать (как шаг 7 `new-plugin`).

## Режим «grade»

- [ ] 1. Прочитай `evals/results/<дата>/факты.md` и `артефакты/`.
- [ ] 2. Прогони каждый градер; при расхождении отчёта агента и файлов
      первичны файлы.
- [ ] 3. Правила недетерминизма (§9): на приёмке 2 прогона на кейс.
- [ ] 4. Запиши `вердикт.md` по формату §8; каждый FAIL — с градером и
      уликой (файл + место).

## Ограничения

- `evals/` и `results/` — внутренние QA-материалы: не переносить в
  `plugins/` и не пушить (§11).
- Прогон на стенде выполняет пользователь (или `deploy-plugin` для
  установки); команда не имитирует результаты прогона.

## Формат отчёта

Сборка: дерево `evals/`, список кейсов с типом, открытые `<TBD>`.
Grade: таблица вердикта и итог PASS/FAIL.
