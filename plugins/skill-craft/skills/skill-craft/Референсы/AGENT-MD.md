# Стандарт агента плагина (`agents/<alias>.md`)

> **Источник:** указание пользователя 2026-10-05 — агент обязателен в
> каждом плагине. Структура обобщена по агентам каталога `plugins/`
> (14 из 16 используют разделы «Роль / Навыки / Принципы / Границы»).
> Не часть присланного контракта: контракт витрины (`METHODOLOGY.md` §4)
> допускает плагин без агента, это правило его ужесточает.

## 1. Зачем агент

Агент — сердце плагина. Навыки описывают, *как* делать отдельную задачу;
агент решает, *кто* он для пользователя, *какой* навык запускать на какой
фазе и *где* его зона заканчивается. При развёртывании тело агента
становится полем «Инструкция» агента на стенде (`auto-test.md` §4):
без файла агента стенд получает пустую или выдуманную инструкцию, а
навыки — без маршрутизации между ними.

## 2. Контракт файла

- Путь: `plugins/<plugin-alias>/agents/<agent-alias>.md`; alias — по
  правилам `METHODOLOGY.md` (латиница, цифры, дефис, подчёркивание,
  ≤ 64 символов).
- В плагине **минимум один** агент (лимит контракта — до 20). Главный
  агент по умолчанию — `agents/<plugin-alias>.md`; иное имя допустимо,
  если оно точнее называет роль (образец — `pro-meetings/agents/meeting-analyst.md`).
- Каждый навык плагина закреплён хотя бы за одним агентом.

## 3. Заголовок

| Поле | Обяз. | Правило |
|---|---|---|
| `name` | да | **роль** — существительное-деятель («Рекрутер», «AI-Бухгалтер», «Аналитик встреч руководителя»). Исключение из правила отглагольного `name` навыков. Одна строка без «: » |
| `description` | да | что агент ведёт + охват («от … до …»); одна plain-строка по канону `METHODOLOGY.md` (без `\|-`, кавычек, «: ») |
| `skills` | да | **все** навыки плагина, которые ведёт агент, и **только** они: каждый alias существует в `skills/`; чужие и внешние навыки не проходят проверку витрины |
| `temperature` | нет | 0.2 — расчёты, учёт, право; 0.3 — по умолчанию; 0.4–0.5 — тексты, маркетинг |
| `model` | нет | не указывать без требования черновика |

Стенд поля `skills` и `temperature` при ручном развёртывании игнорирует
(привязка навыков — отдельным шагом, `auto-test.md` §7), но витрина их
проверяет — заполнять всегда.

## 4. Тело

Обращение на «ты», вступительный абзац — одна-две фразы: кто агент и для
кого. Дальше обязательные разделы в этом порядке:

| Раздел | Что внутри |
|---|---|
| `## Роль` | экспертиза, с кем работает, режим (assist / HITL), чем помогает |
| `## Навыки` | нумерованный список: **Название** (`alias`) — когда применять и что даёт; по пункту на каждый навык из `skills` |
| `## Принципы` | первым пунктом — маршрутизация «ситуация → навык» (при 4+ навыках — отдельный раздел `## Маршрутизация` или «Навыки по фазам работы»); дальше — без выдумок, HITL для решений, документ-след |
| `## Границы` | что вне зоны; что решает только человек; куда направлять смежные задачи (другой плагин — по имени и alias) |

Необязательные разделы — когда черновик их требует: протоколы
уточнения через `question` (тип отчёта, источник данных), формат
ответа, работа с источниками, режимы данных.

Правила тела:

- 25–150 строк. Агент маршрутизирует, а не исполняет: шаги, шаблоны и
  справочники — в навыках; текст навыков в агент не копировать.
- Ограничения harness (`sys-*`, `/session`, `question`) — только там, где
  они касаются поведения агента между навыками.
- Факты — только из черновика и навыков; недостающее — `<TBD: что уточнить>`.

## 5. Шаблон

```markdown
---
name: <Роль>
description: Ведёт <область> — от <начало> до <результат>
skills: [<skill-a>, <skill-b>]
temperature: 0.3
---

Ты — <роль> для <кого>, отвечающий за <зону>.

## Роль
<Экспертиза, режим работы, с кем взаимодействует.>

## Навыки
1. **<Название навыка>** (`<skill-a>`) — когда <ситуация>; даёт <результат>.
2. **<Название навыка>** (`<skill-b>`) — когда <ситуация>; даёт <результат>.

## Принципы
1. **Определи фазу.** <ситуация> → `<skill-a>`; <ситуация> → `<skill-b>`.
2. **Без выдумок.** <на чём основаны выводы; что делать при нехватке данных>.
3. **Рекомендация ≠ решение.** <что решает человек>.
4. **Документ-след.** <в каком формате фиксируется результат>.

## Границы
- <Что вне зоны.>
- <Смежная задача> — плагин «<Название>» (`<alias>`).
```

## 7. Чек-лист агента

- [ ] Есть хотя бы один `agents/*.md`.
- [ ] `name` — роль; `description` — plain-строка по канону.
- [ ] `skills` ↔ `skills/` плагина: каждый alias существует; каждый
      навык плагина закреплён за агентом.
- [ ] Разделы «Роль», «Навыки», «Принципы», «Границы» на месте.
- [ ] Маршрутизация «ситуация → навык» покрывает все навыки.
- [ ] В «Границах» указано, что решает человек.
- [ ] Тело 25–150 строк; содержимое навыков не дублируется.
